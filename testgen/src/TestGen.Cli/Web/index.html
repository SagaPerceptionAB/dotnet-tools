TestGen

Kör testerna och läs resultatet här. Själva testerna skriver du fortfarande i Excel.

Så här gör du

  1. Välj API-beskrivning och skriv API-adressen. Fälten märkta (krävs) måste fyllas i, resten är valfria.
  2. Tryck Kör tester. Resultaten dyker upp medan testerna körs.
  3. Läs korten märkta FEL och spara rapporten till utvecklaren.
Vad betyder orden?
API
Ett system som andra program kan prata med, t.ex. en webbshop som tar emot beställningar. Det är API:et som testas här.
API-beskrivning
En fil (kallas OpenAPI) som beskriver vilka anrop systemet förstår. Be utvecklaren om den. Testerna skapas utifrån den.
Miljö
Ett ställe där systemet körs, t.ex. "test" eller "lokal". Varje miljö har en egen adress. De skrivs i testgen.yaml.
Statuskod
Ett tresiffrigt svar från systemet. 200 betyder OK, 4xx (t.ex. 400 eller 404) betyder att systemet sa nej till anropet, 5xx (t.ex. 500) betyder att systemet kraschade.
Token
En inloggningsnyckel som du fått av utvecklaren. Den behövs om systemet kräver inloggning.
Slumpfrö
Ett tal som styr den slumpade testdatan. Samma tal ger samma testdata. Ett annat tal ger nya uppgifter, vilket hjälper om systemet svarar att något "redan finns" (409).
OK
Testet gav det svar som väntades.
FEL
Testet gav ett annat svar än väntat. Det är dem du behöver titta på.
HOPPAD
Testet kunde inte köras, oftast för att ett tidigare steg misslyckades.
Solution
Filen (.sln eller .slnx) som samlar all källkod till systemet. Systemkartan läser den.
Integration
Något utanför systemet som systemet pratar med, t.ex. en databas, ett annat system, en kö eller e-post.
Systemkarta
En bild av vägen ett anrop tar genom systemets kod och ut till integrationerna.

Kör tester

Systemet som ska testas. Adress och API-beskrivning fylls i efter valet.
Länken eller filen (.json, .yaml, .yml) som beskriver systemets anrop. Skriv länken eller sökvägen, eller välj filen. Be utvecklaren om den – länken slutar ofta på /openapi.json eller /swagger/v1/swagger.json.
Filen där du skriver dina egna tester. Skriv sökvägen eller välj filen. Utan Excel-fil körs bara de tester som skapas automatiskt.
En miljö är ett ställe där systemet körs, t.ex. "test". Miljöerna läses ur testgen.yaml.
Adressen till systemet som ska testas. Fylls i av miljön, men du kan ändra den.
Nyckel du fått av utvecklaren. Lämna tomt om miljön i testgen.yaml redan har en token. Sparas inte.
Kör bara det du skrivit i Excel-filen. De automatiskt skapade testerna hoppas över.
Scenarier
Välj vilka scenarier i Excel-filen som ska köras. Inget valt = alla.
Fler inställningar (alla valfria)
Testdatan slumpas fram. Samma tal ger samma testdata varje gång. Tomt = 12345. Svarar systemet att något "redan finns" (409) kan du prova ett annat tal.
Bara ett anrop (namnet i API-beskrivningen, t.ex. createOrder). Tomt = alla.
Så många sekunder väntar varje test på svar innan det räknas som misslyckat. Tomt = 30.
